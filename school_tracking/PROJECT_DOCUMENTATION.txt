SECTION 1 — WHAT IS THIS SYSTEM?
────────────────────────────────────────────────────────────────────────────────

The Smart School Tracking System is a web-based School Management System built
with PHP and MySQL. It allows a school to manage students, teachers, parents,
attendance, grades, assignments, and notifications — all from a web browser.

There are FOUR types of users (roles):

  1. ADMIN    — manages everything (users, classes, reports, notifications)
  2. TEACHER  — records attendance, grades, creates assignments, sends notices
  3. STUDENT  — views own attendance, grades, submits assignments, reads inbox
  4. PARENT   — monitors their child's attendance, grades, and notifications

Each role sees a different dashboard and menu after logging in.
The system prevents one role from accessing another role's pages.

Entry point: http://localhost/school_tracking
  → index.php immediately redirects logged-in users to their dashboard,
    and redirects guests to the login page.
  → login.php is the public-facing entry point with a split-screen layout.

SECTION 3 — DATABASE TABLES (11 tables)
────────────────────────────────────────────────────────────────────────────────

The database is called: school_tracking_db
It has 11 tables. Here is what each one stores:

  TABLE 1: users
  ──────────────
  Stores every person who can log in.
  Columns: user_id, username, password (hashed), role, full_name,
           email, phone, created_at, last_login, failed_attempts
  One row per person (admin, teacher, student, or parent).

  TABLE 2: classes
  ────────────────
  Stores school classes/classrooms.
  Columns: class_id, class_name, academic_year, schedule, capacity, created_at
  Example row: "Class 10A", "2025-2026", "Mon-Fri 08:00-14:00", capacity 30

  TABLE 3: students
  ─────────────────
  Extra profile info for users who are students.
  Columns: student_id, user_id (links to users), class_id (which class),
           date_of_birth, gender, created_at
  A student has one row in "users" AND one row in "students".

  TABLE 4: teachers
  ─────────────────
  Extra profile info for users who are teachers.
  Columns: teacher_id, user_id (links to users), subject_specialty, created_at
  Example: teacher_id=1, subject_specialty="Mathematics & Science"

  TABLE 5: parents
  ────────────────
  Links a parent to their child (student).
  Columns: parent_id, user_id (the parent), student_id (their child),
           relationship (e.g. "Father"), created_at
  One parent can be linked to multiple children.

  TABLE 6: class_teachers
  ───────────────────────
  Many-to-many link between classes and teachers.
  Columns: class_id, teacher_id
  A class can have multiple teachers; a teacher can teach multiple classes.

  TABLE 7: assignments
  ────────────────────
  Stores homework/assignments created by teachers.
  Columns: assignment_id, teacher_id, class_id, title, description,
           file_path (optional attached file), deadline, created_at

  TABLE 8: attendance
  ───────────────────
  Stores attendance records (one row per student per day).
  Columns: attendance_id, student_id, teacher_id, class_id,
           date, status (present / absent / late), created_at
  UNIQUE KEY on (student_id, date) prevents duplicate entries.

  TABLE 9: grades
  ───────────────
  Stores exam/quiz grades given to students.
  Columns: grade_id, student_id, teacher_id, class_id, assignment_id,
           subject, grade_value (0.00 to 100.00), exam_type, remarks, graded_at
  Grade labels: A=90+, B=70-89, C=50-69, F=below 50

  TABLE 10: notifications
  ───────────────────────
  Stores messages sent from admin/teachers to specific recipients or groups.
  Columns: notification_id, sender_id, recipient_id (user or NULL),
           title, message, is_read (0=unread, 1=read), created_at
  If recipient_id is NULL → it is a broadcast (sent to everyone in target group).

  TABLE 11: assignment_submissions
  ─────────────────────────────────
  Stores files uploaded by students for assignments.
  Columns: submission_id, assignment_id, student_id, file_path, submitted_at

FILE: index.php
  What it does: Redirect-only entry point. Contains no HTML or UI.
  Behavior:
    - If logged in → redirect to /<role>/index.php (e.g. /admin/index.php)
    - If not logged in → redirect to /school_tracking/login.php
  There is NO landing/home page. Login page is the public entry point.

FILE: login.php
  What it does: The login page for ALL roles (admin, teacher, student, parent).
  Layout: Split-screen — left panel is branding, right panel is the login form.
  Left panel includes:
    - Brand: "Smart School Tracking System" / "School Management Platform"
    - Tagline about modern school management
    - 6-feature icon grid (attendance, grades, assignments, notifications,
      analytics, parent portal)
    - 4 role chips (Admin, Teacher, Student, Parent)
    - Stats bar (e.g. 99.9% uptime, live data, multi-role)
  Right panel includes:
    - Username + password fields
    - Password show/hide toggle
    - After 5 wrong attempts → account locked for 15 minutes (security)
    - Uses PHP password_verify() to check hashed passwords
    - On success → redirects to the correct role dashboard
  Browser tab title: "Sign In — Smart School Tracking System"

FILE: logout.php
  What it does: Destroys the PHP session and redirects to login page.
  When used: When any user clicks "Logout" in the top navbar.

FILE: config/db.php
  What it does: Connects to the MySQL database using PDO.
  Settings: host=127.0.0.1, port=3307, database=school_tracking_db, user=root
  Returns: A $pdo object used by every other PHP file to run SQL queries.
  Every page starts with: $pdo = require __DIR__ . '/../config/db.php';

FILE: includes/auth.php
  What it does: Security — makes sure users are logged in and in the right role.
  Functions:
    - requireLogin()  → if not logged in, redirect to login.php
    - requireRole('teacher') → if wrong role, show "Access Denied"
    - isLoggedIn() → returns true/false
    - getCurrentUser() → returns array of current user data from session
  Every protected page starts with requireLogin() and requireRole().

FILE: includes/header.php
  What it does: Outputs the top navbar shown on every page after login.
  Contains:
    - Logo icon + "Smart School Tracker" / "School Management System" text
    - Hamburger menu button (for mobile, shown only when logged in)
    - User avatar showing logged-in user's initials (generated by getInitials())
    - Full name and role label in the navbar
    - Logout button linking to logout.php
    - HTML <head> with links to CSS, Google Fonts, Font Awesome (CDN)
  Browser tab title: "Smart School Tracking System"

FILE: includes/footer.php
  What it does: Outputs the closing HTML and loads JavaScript files.
  Loads: Chart.js 4.4.0 (from CDN) and assets/js/main.js
  Footer text: "© [year] Smart School Tracking System. All rights reserved."

FILE: includes/functions.php
  What it does: Small helper functions used across the project.
  Functions:
    - setFlash() / getFlash() → store and show one-time success/error messages
    - showFlash() → displays the flash message with the right icon
    - formatDate() → converts database date format to readable format

FILE: assets/css/style.css
  What it does: All visual styling for the entire website.
  Contains:
    - CSS variables for color palette (navy blue theme):
        --primary: #1e3a5f  --primary-light: #2d5a8e  --primary-dark: #0f1f33
    - Navbar, sidebar, card, table, button, badge, form styles
    - Login split-screen layout (.login-left, .login-right, .login-left-inner)
    - Login left panel: uses justify-content:space-between for even distribution
    - Stat card gradient icon colors (green, blue, orange, red, purple, etc.)
    - Scrollable checkbox list (.checkbox-scroll-list) for teacher/student selection
    - Modal overlay styles (.modal-overlay, .modal-box, .modal-header)
    - Mobile responsive breakpoints

FILE: assets/js/main.js
  What it does: Shared JavaScript interactivity (loaded on every page via footer).
  Features:
    - Sidebar toggle (open/close on mobile with hamburger button)
    - Alert auto-dismiss (success messages disappear after 5 seconds)
    - Delete confirmation popup (asks "Are you sure?" before deleting)
    - File size validation (rejects files over 10MB before upload)
    - Form validation for .needs-validation forms (highlights empty required fields)
    - Live table search/filter using [data-search] attribute
    - Password show/hide toggle (.password-toggle button)
    - Landing navbar scroll effect (.landing-nav)
    - Counter animation on .stat-value elements (IntersectionObserver)
    - Select All / Clear All for checkbox groups ([data-select-all] buttons)
  NOTE: main.js does NOT contain handleRecipientType() — each notification
        page defines its own version to avoid conflicts.

FILE: admin/manage_classes.php  (Class Management)
  What it does: The admin creates and manages school classes.
  Features:
    - Add class: name, academic year, schedule, capacity
    - Assign one or more teachers using scrollable checkbox list (same style
      as student selection — checkboxes with Select All / Clear All buttons)
    - Assign students to a class via scrollable checkbox list
    - Edit class details (all fields including teachers and students)
    - Delete class (warns if students are enrolled)
    - Table shows: class name, year, teacher(s) with subject, enrolled count,
      capacity, and a "Details" button
    - "Details" button → opens Class Details Modal:
        Modal shows: class info (year, schedule, capacity)
        Teachers section: scrollable list of assigned teachers with subjects
        Students section: scrollable list of enrolled students
  Teacher/student selection uses scrollable checkbox lists (not chip UI).
  POST data for teacher_ids[] and student_ids[] is restored on validation
  failure so selections are preserved if the form has errors.

FILE: admin/notifications.php  (Send Notifications)
  What it does: Admin sends messages to any group or individual in the system.
  Recipient types (9 options):
    - Broadcast to ALL users
    - All Students (system-wide)
    - All Teachers (system-wide)
    - All Parents (system-wide)
    - All Students in a Class → shows class dropdown
    - All Parents of a Class → shows class dropdown
    - Specific Student → shows class dropdown first, then student dropdown
                         (student list populates dynamically based on class)
    - Specific Teacher → shows teacher dropdown
    - Specific Parent  → shows class dropdown first, then student dropdown
                         (finds parent linked to that student)
  JS cascade: filterStudentsByClass(classId) fills the student dropdown using
  $studentsByClass data JSON-encoded into the page from PHP.
  handleRecipientType(type) controls which field groups are shown/hidden.
  Also shows: Sent notifications history (last 30 batches).
  Broadcast warning banner shown when "Broadcast to ALL" is selected.

FILE: admin/inbox.php  (Admin Inbox)
  What it does: Admin reads notifications sent to them personally.
  Features:
    - Lists all notifications where recipient_id = admin's user_id or NULL
    - Unread notifications highlighted with blue left border and "New" badge
    - "Mark as Read" button on unread messages
    - Pagination: 10 notifications per page
    - Shows: sender name, sent date/time, title, full message

FILE: admin/reports.php  (Reports)
  What it does: Generate and print data reports.
  Report types available:
    - Attendance Report: filter by class, month — shows each student's records
    - Grade Report: filter by class, subject — shows all grades
  Features:
    - Dropdown filters (class, month, subject)
    - Results shown in a table
    - Print button to print the report directly from browser

SECTION 6 — HOW THE LOGIN AND SECURITY WORKS
────────────────────────────────────────────────────────────────────────────────

  1. All passwords are HASHED using PHP's password_hash() (bcrypt algorithm).
     Stored passwords in the database are NOT readable — they look like:
     "$2y$10$CP4TBAuB.Y8rYaJnk1bwNeUI..."

  2. Login check uses password_verify() — it compares the typed password
     against the stored hash without ever storing the plain text.

  3. Account lockout: after 5 wrong password attempts, the account is locked
     for 15 minutes. The failed_attempts count is stored in the users table.

  4. Sessions: when login succeeds, PHP stores the user's id and role in
     a session variable ($_SESSION['user_id'] and $_SESSION['role']).

  5. Every protected page calls requireLogin() and requireRole() from auth.php.
     These check the session — if the session is missing or the role is wrong,
     the user is immediately redirected to login.php.

  6. All database queries use PDO prepared statements to prevent SQL Injection.

  7. All output uses htmlspecialchars() to prevent XSS attacks.
     JSON data embedded in pages uses JSON_HEX_TAG | JSON_HEX_APOS | JSON_HEX_AMP.

  8. File uploads (assignments, submissions) are validated by both extension
     and MIME type, and renamed to random names to prevent path attacks.

SECTION 12 — NOTIFICATION SYSTEM DETAILS
────────────────────────────────────────────────────────────────────────────────

  The notification system allows admin and teachers to send targeted messages.

  RECIPIENT TYPES (admin/notifications.php and teacher/notifications.php):
  ─────────────────────────────────────────────────────────────────────────
  broadcast_all      → sends to every user in the system
  all_students       → sends to every student
  all_teachers       → sends to every teacher (admin only)
  all_parents        → sends to every parent (admin only)
  class_students     → sends to all students in a chosen class
  class_parents      → sends to all parents of students in a chosen class
  specific_student   → Step 1: choose class → Step 2: choose student from that class
  specific_teacher   → choose teacher from dropdown (admin only)
  specific_parent    → Step 1: choose class → Step 2: choose student → sends to their parent

  HOW THE CLASS→STUDENT CASCADE WORKS:
  ─────────────────────────────────────
  PHP builds $studentsByClass: an associative array keyed by class_id,
  each value being an array of {user_id, full_name} for students in that class.
  This is JSON-encoded into the page as a JS variable.
  When a class is selected, filterStudentsByClass(classId) reads that data
  and populates the student <select> element dynamically.

  INBOXES:
  ─────────────────────────────────────
  Every role has a notification inbox:
    admin   → admin/inbox.php
    teacher → teacher/inbox.php
    student → student/notifications.php
    parent  → parent/notifications.php
  Each inbox shows notifications where recipient_id = that user's ID,
  plus NULL (broadcast) notifications. Unread items are highlighted and
  can be marked as read individually.

  IMPORTANT IMPLEMENTATION NOTE:
  ─────────────────────────────────────
  main.js does NOT define handleRecipientType(). Each notification send
  page defines its own version inline. This prevents main.js from silently
  overriding the page-level function after DOMContentLoaded fires.
